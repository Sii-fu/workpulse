# WorkPulse

Single-user daily work tracker: log work, run task timers, and generate AI standups and end-of-day
timesheets. React 19 SPA served by a thin Express server. All data lives in browser localStorage,
with optional Gemini AI and Google Sheets sync. (Originally generated by Google AI Studio.)

## Commands

| Command | What it does |
|---|---|
| `npm run dev` | `tsx server.ts`: Express + Vite middleware with live reload at **http://localhost:3000** (`PORT` overrides) |
| `npm run build` | `vite build` → `dist/` (production: `NODE_ENV=production npm start` serves `dist/`) |
| `npm test` | `vitest run`: unit tests in `src/**/*.test.ts` |
| `npm run lint` | `tsc --noEmit`. This is a **type-check only**; there is no ESLint |
| `python tests/smoke/tick_cost.py` | Main-thread ms per second while a timer runs, per theme and screen (compare before/after a change; start the dev server first) |
| `npm run test:smoke` | Browser smoke test (`tests/smoke/smoke.py`, Python Playwright): log, edit, timers, every task stage, 4 themes x modes, modal Escape. Starts its own dev server, so stop any server on port 3000 first. Run after every design phase; selectors live in its `SEL` map |
| `run.bat` / `run.bat prod` | Windows one-click launcher: checks Node, installs deps when `package.json` changes, creates `.env.local`, picks a free port, opens the browser. `NO_BROWSER=1` skips the browser |

- Tests: `npm test` (Vitest, node environment, in-memory localStorage stub in `src/test/`). Pure helpers get unit tests; UI changes still need `npm run lint` plus a browser check (the webapp-testing skill).
- `npm run clean` uses `rm -rf` and fails in cmd.exe; use Git Bash or delete `dist/` by hand.

## Architecture

- `src/App.tsx` owns **all** state (logs, backlog, projects, tags, settings, modals) and every handler.
  It also runs a **1-second `setInterval`** that ticks `elapsedSeconds` on in-progress tasks and saves the
  backlog each tick. Components are presentational and receive props and callbacks.
- **Storage**: `src/utils/storage.ts` reads and writes localStorage keys `workpulse_logs`, `workpulse_backlog`,
  `workpulse_projects`, `workpulse_tags`, `workpulse_settings`, `workpulse_active_draft`.
  `loadStoredData()` falls back to `src/data/seedData.ts` and rolls unfinished past-due tasks over to today.
- **Data types**: `src/types.ts` defines `WorkLog`, `BacklogTask` (stages: planned → in_progress → paused/blocked → done), `Project`, and `AppSettings`.
- **Server** (`server.ts`) is a thin proxy with no database:
  - `POST /api/gemini/generate` handles AI standup text (`src/utils/aiGenerator.ts` builds the prompt and has offline templates)
  - `POST /api/synthesize-eod` groups tasks by project × status, then tries a cascade of Gemini models with a template fallback
  - `POST /api/sheets/proxy` forwards to the user's Google Apps Script URL (avoids CORS). The script source is in `src/utils/googleAppsScriptTemplate.ts`
  - `POST /api/activity/scan` and `POST /api/activity/suggest` read the user's git commits and Claude Code history and group them with Gemini (see **Activity suggestions** under Gotchas)
  - `GET /api/health`
  - Dev mode mounts Vite as middleware; HMR shares the same HTTP server and port
- **Themes**: `modern` (default), `minimalist`, `compact`, `matrix`. `App.tsx` sets `data-theme`/`data-mode` on
  `<html>`; colors are CSS variables in `src/index.css`. Modern renders `DailyLogger` + `TimelineFeed` + `CommandSidebar`;
  the other three each have a layout in `src/components/themes/` with a one-line quick-log input. All four timelines
  take the same `LogListProps` (`src/components/feed/types.ts`) and build on shared pieces: `useLogFilters`,
  `useQuickLog`, `useFocusLog` (search-palette jump) in `src/hooks/`; `LogFilterBar`, `SelectionBar`, `LogActions`,
  `StatusBadge`, `MicroTasks` in `src/components/feed/`. Editing a log or "Add details" opens the full `DailyLogger`
  form in `LogEditorDialog` for the three non-Modern themes. Add a log feature once in those shared pieces, not per theme.
  Filtering rules are in `src/utils/logFilter.ts`; the four top-level tabs are `NAV_TABS` in `src/utils/nav.ts`.
- **Look and feel** (P3 of the design overhaul): surfaces are flat and opaque (no glass, glow or gradients), type is per theme
  (`--font-display/body/mono` in each theme block of `index.css`: Modern Instrument Sans, Minimalist Literata + Atkinson
  Hyperlegible, Compact IBM Plex, Matrix JetBrains Mono), and each theme has one accent that marks "live" and the primary
  action. Minimum text size is 12 px (`text-xs`); do not add `text-[10px]`. The running task is shown by `RunningStrip`
  under the top bar on every screen. The theme switch is `ThemeMenu` in the top bar and applies at once. Matrix scanlines
  are off unless `AppSettings.crtEffect` is on (`data-crt="on"` on `<html>`).
- **Shared UI primitives** live in `src/components/ui/`: `ModalShell` (every dialog uses it: `role="dialog"`, Escape, focus trap and focus restore) and `IconButton` (icon-only buttons need a `label`). New dialogs and icon buttons should use them, not hand-rolled markup. Focus ring, 24 px minimum target size and reduced-motion handling are global rules in `src/index.css`.
- **Styling**: Tailwind v4 (via `@tailwindcss/vite`) plus theme CSS variables; icons from `lucide-react`.
- **Config**: `GEMINI_API_KEY` from `.env.local` / `.env` (dotenv), or a key entered in Settings (stored in localStorage, which takes priority).

## Gotchas

- **Dates are LOCAL** (`src/utils/dates.ts`: `localDateStr()`, `localTimeStr()`, `rangeStart()`, `lastNDays()`). Logs and tasks
  store `YYYY-MM-DD` in the user's timezone (UTC+6), so work at 02:00 counts for that day. Never build a date with
  `toISOString().split('T')[0]` (that is UTC), and compare dates as strings, not with `new Date("YYYY-MM-DD")`.
  ISO timestamps (`createdAt`, `completedAt`) stay UTC; convert with `localDateOfIso()` before comparing to a date.
  Tests that touch dates set `process.env.TZ = 'Asia/Dhaka'`. Task rollover also runs when the date changes while the app is open.
- **The Tasks screen is split** (`src/components/BacklogSection.tsx` is a thin shell). State and handlers live in
  `src/components/tasks/useTasksModel.ts`; the shared header in `TasksHeader.tsx`; one view per theme
  (`ModernTasksView`, `MinimalistTasksView`, `CompactTasksView`, `MatrixTasksView`). The views are big (500-850 lines each):
  search them (Grep for the label or handler) and read small ranges. Running clocks must be `<TaskClock>` / `<GroupClock>`
  (`tasks/Clock.tsx`), never `task.elapsedSeconds` in JSX: the screen is memoized and ignores elapsed-time ticks, and the
  clocks read live seconds from `src/utils/timerStore.ts`. Handlers passed to it from App go through `useStableCallback`.
- **Changing a data type needs a localStorage migration.** Users have saved data without the new field.
  Use the `data-model-change` skill.
- **Unused dependencies** (nothing imports them; remove only if asked): `motion`, `autoprefixer`.
- **Gemini model names live in one list**, `GEMINI_MODEL_CASCADE` in `src/utils/geminiModels.ts`, used by both
  `/api/gemini/generate` and `/api/synthesize-eod`. If AI output falls back to templates, the UI now shows the reason; check
  these names first.
- **Sample data**: the demo logs, tasks and projects a new colleague starts with are recognised by their fixed ids
  (`src/data/sampleData.ts`, no field on any record). They carry a "Sample data" label, a banner offers one-click
  "Clear sample data" with Undo, and `unsyncedLogs` never sends them to the Sheet. Never give a real item an id like
  `log-1`/`task-1`/`proj-1`: real ids always include a timestamp.
- **Backups**: Settings → Data & Backup writes/imports one JSON file (`src/utils/backup.ts`; never contains the Gemini key
  or `lastBackupAt`). `AppSettings.lastBackupAt` (optional, device-only) is set by `handleBackupNow` in `App.tsx` and drives
  `BackupReminder` (`src/utils/backupReminder.ts`: due after 7 days, or never, and only once there is non-sample data).
  The automatic backups taken before Reset / Start fresh / Fix dates do **not** count, because the data changes right after.
- **Failures are plain sentences**: AI and Sheet errors go through `src/utils/aiErrors.ts` (`plainAiMessage`,
  `plainSheetMessage`) so no raw "Failed to fetch" reaches the UI; a failed sync toast carries Retry.
- **Durations come only from tracked time** (`minutesFromSeconds` in `src/utils/duration.ts`): no invented defaults or minimums.
  **One exception: activity suggestions** (below). Their minutes are an estimate (`estimateMinutes` in
  `src/utils/activity/time.ts`: a gap over 30 minutes ends a cluster, each cluster counts its span with a 5-minute floor),
  labelled "estimated" and editable in the dialog before adding. Once added, the log holds a plain number. Do not reuse
  that estimate anywhere else.
- **Activity suggestions** ("Suggest logs" in the top bar, and a button in End of day): the server reads the day's git commits
  and, only if the user opted in, Claude Code prompts from folders listed in Settings → Activity suggestions, and Gemini
  groups them into suggested logs the user ticks and adds.
  - Server side: `src/server/activityReaders.ts` (Claude session JSONL is streamed and files older than the day are skipped by
    mtime; git uses `--all`, per-repo `user.name`, de-dup by hash), `src/server/activityGuard.ts`. Claude's JSONL format is
    internal and can change, so parsing is defensive and unknown lines are skipped. Terminal history is deliberately not supported
    (no timestamps).
  - Both routes answer only while bound to `127.0.0.1` **and** when the `Host` header is exactly `localhost:<PORT>` or
    `127.0.0.1:<PORT>` (`isStrictLocalHost`; `ALLOWED_HOSTS` does not widen it). Never relax this: the routes read local files.
  - Client side: `src/utils/activity/` (pure, unit-tested: `pipeline.ts` is the whole flow, `suggestions.ts`, `aiTasks.ts`,
    `time.ts`, `sanitize.ts`, `settings.ts`) and `src/components/activity/`. Gemini only returns `{ text, itemIds[] }`; minutes,
    project and evidence are computed in code from the items. Text is redacted (`redactSecrets`) and clipped before leaving the machine.
  - Data: `WorkLog.sourceIds` lists the activity ids a log used (they are not suggested again; deleting the log frees them; it is
    never sent to the Sheet and `handleDuplicateLog` clears it). `AppSettings.activityFolders` is device-specific, so it is **not**
    in backups. Git commits are on unless `activityUseGit === false`; Claude prompts are off unless `activityUseClaude === true`.
  - The dialog must not scan until the user has accepted the data notice (`'idle'` phase in `ActivitySuggestionsDialog`); the
    `activity_suggestions` smoke check enforces this. Adding several logs at once goes through `handleAddLogs`, not a loop over `handleAddLog`
    (each call would start from the same stale `logs`). On phones the top bar hides "Suggest logs" (every control is 44 px
    wide there, so a third report button pushes the theme toggle off screen); the dialog opens from End of day instead.
- **Task logging**: `BacklogTask.loggedSeconds` records time already written into a log; EOD only logs the rest
  (`src/utils/taskLogging.ts`). **Marking a task done does not create a log** (`handleCompleteTask` in `App.tsx`): it waits in
  Completed Today until the user selects it and uses "Timesheet from selected" (or End of day). Only the explicit "Log" / "Push"
  buttons (`handleConvertTaskToLog`) write a log straight from a task.
- The Apps Script writes fixed sheet columns and upserts rows by log `Id` (12th column); changing it requires the user to redeploy their script. The app tracks `WorkLog.syncedAt` and `AppSettings.syncTrackingSince` so manual Sync sends only unsynced logs and never re-sends history.
- The server binds `127.0.0.1` by default (`HOST=0.0.0.0` opts in to LAN access, which has no authentication). `/api/sheets/proxy` only forwards to `https://script.google.com/macros/s/...` URLs.
- Never read or print `.env.local` / `.env` (denied in `.claude/settings.json`).

## Coding rules

- **Think before coding.** State your assumptions. If a request is ambiguous, ask instead of guessing.
- **Simplicity first.** Write the minimum code that solves the problem, with no speculative features, options or abstractions.
- **Surgical changes.** Touch only what the task needs. Don't refactor, reformat or "improve" unrelated code.
  Match the existing style (functional components, `React.FC<Props>`, Tailwind classes, theme CSS variables).
- **Goal-driven.** Before starting, say how success will be verified (usually: `npm run lint` passes, and the behavior is
  checked in the browser at http://localhost:3000). Verify before saying it's done, and report failures honestly.

## Workflow

- **Small bug fix**: use plan mode plus the rules above. Don't run Superpowers' full brainstorm/plan flow.
- **New feature or multi-file change**: use Superpowers (brainstorm → plan → execute).
- **Data model change**: use the `data-model-change` skill.
- **UI verification**: use the `webapp-testing` skill with Python Playwright against `npm run dev` (http://localhost:3000).
  Run its helper from the repo root, e.g.
  `python .claude/skills/webapp-testing/scripts/with_server.py --server "npm run dev" --port 3000 --timeout 60 -- python <script>.py`.
  Write throwaway scripts and screenshots outside the repo.
- **Before ending a session**: run the `session-handoff` skill (writes `.claude/HANDOFF.md`).
- A Stop hook runs `npm run lint` after each turn and sends type errors back to be fixed.
